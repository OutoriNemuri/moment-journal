# 时刻日记 — Beta 0.2.1 策划案

> 版本：0.2.1 (1)
> 状态：待确认
> 上一版：0.2 (1)

---

## 一、要解决的问题

### 问题：目录出现了两次

0.2 之后，同一份内容在界面上出现了两遍：

```
主界面  = 当前日记本的日记列表     ← 一份目录
侧栏上半 = 当前日记本的日记目录     ← 同一份目录，再来一遍
```

这是 0.2 重构留下的，不是新引入的：当时把「全部日记」换成「当前本的目录」，
但主界面仍然是列表，于是侧栏与主界面展示的是同一批东西。

### 结论：主界面即编辑器

取消「列表页」这一层。主界面直接是编辑器，**默认不打开任何日记**，
显示占位状态。要写作或要继续写，从侧栏目录点击，或按「写日记」新建。

```
┌──────────────┬────────────────────────────────┐
│ 时刻日记      │  写作                          │
├──────────────┤  ──────────────────────────    │
│ 今日          │                                │
│ 昨天          │  选择一篇日记，                │
│ 10-08        │  或按右下角开始新的。           │
│  ·           │                                │
│  ·  （侧栏）  │                                │
│  ·            │                                │
├──────────────┤                                │
│ 日记本        │                                │
│  我的日记 ●   │                                │
│  2026 年      │                                │
└──────────────┴────────────────────────────────┘
```

这样侧栏是唯一的目录，不再重复。

## 二、占位状态

主界面在未打开日记时显示：

- 顶栏保留（有侧栏按钮、备份设置入口）
- 编辑区显示引导文案，**内容不可点击**：引导用户从侧栏打开，或按按钮新建
- **快捷输入栏整体不出现**（没有日记可插入时间或图片）
- 「写日记」按钮照常可用

关键约束：**不能在无日记状态下让用户输入**。否则用户敲了字却无处归属，
要么丢字，要么悄悄创建一篇空日记。因此占位状态下整块编辑区不可编辑，
引导文案本身也不是按钮 —— 它是说明，不是入口。

### 占位状态下的功能可用性

**备份设置移入功能抽屉**，因此抽屉在占位状态下**仍有内容，必须显示**。

| 抽屉内的项 | 占位状态（未打开日记） | 已打开日记 |
|---|:--:|:--:|
| 复制日记 | 不显示 | 可用 |
| 查找 | 不显示 | 可用 |
| 导出 | 不显示 | 可用 |
| 时间 | 不显示 | 可用 |
| **备份** | **可用** | 可用 |

四项编辑功能都需要一篇已打开的日记，因此在占位状态下**不显示**，
而不是显示了点不动 —— 沿用 0.2 对新建按钮的处理方式。
备份与日记无关，任何状态下都可用。

这也修正了我先前的一个判断：我曾认为占位状态下应隐藏整个抽屉，
理由是「空抽屉没有意义」。备份移入之后这个前提就不成立了。

## 三、导航结构变更

现有两级路由将被压平。

| 现状 | 改为 |
|---|---|
| `HOME` → 列表页 | **取消**，不再有独立的列表页 |
| `EDITOR/{entryId}` → 编辑器 | 编辑器成为根，路由为 `EDITOR/{entryId?}`，id 可缺省 |
| 侧栏目录点击 → 进入 `EDITOR/{id}` | 同上，切换当前日记 |

要点：

- 编辑器成为**根目标**，`entryId` 允许缺省，缺省即占位状态。
- 从侧栏切换日记时，**不产生新的返回栈**（它是「换一篇」而不是「进一层」），
  否则用户按返回会一层层退回去，体验割裂。
- 退出编辑器不再需要「返回」按钮 —— 它已是主界面。返回键在占位状态下
  应退出应用（或回到桌面），而不是留在应用内的某个中间页。

## 四、侧栏形态（已确认）

**除平板外，一律从左边划出，覆盖在内容之上。平板常驻并排。**

```
平板          手机（含横屏）       折叠屏展开？
┌─────┬──────┐  ┌────────────┐    ┌─────┬──────┐
│侧栏 │编辑器│  │  编辑器     │    │侧栏 │编辑器│
│常驻 │      │  │            │    │常驻 │      │
└─────┴──────┘  └────────────┘    └─────┴──────┘
                 划出时覆盖其上
```

### 判定依据是设备类型，不是屏幕宽度

这一点要说清楚，因为它容易想当然：判定用**是否为平板**，而不是「可用宽度是否达到某个阈值」。
手机横屏时宽度可能超过某些平板，但仍然是手机，仍然是划出。

原因：屏幕宽度是连续量，阈值是人为划的，横竖屏切换时会在两种形态之间跳变；
而设备类型是稳定的，用户对「我这台是手机」的预期也是稳定的。

### 实现

现有代码用的 `ModalNavigationDrawer` **正是「从左边划出、覆盖在内容上」**，
因此**不需要替换**，平板之外的形态已经是对的。

需要新增的只是平板分支：

- 平板：常驻侧栏 + 编辑器并排。
- 其他：维持 `ModalNavigationDrawer`。

两种形态共用同一份侧栏内容函数，只是容器不同 —— 这也是当前实现的写法，
内容函数已是独立的 `Sidebar`，容器换成平板用的常驻布局即可。

## 五、顶栏按钮同级（已确认）

编辑器成为主界面后，**左上侧栏按钮与右上功能抽屉按钮位于同一个顶栏上**，
天然同级。企划原文「放在编辑界面右上，和左上侧栏按钮同级」由此才成立 ——
在此之前编辑器是二级页面，两者不在同一层级，这句话落不了地。

### 具体的后果

**两个按钮在占位状态下都保留。**

- 侧栏按钮：必须保留，它是占位状态下打开日记的唯一入口。
- 功能抽屉按钮：**保留但不出现内容**。占位状态下四项功能全部需要
  一篇已打开的日记，点开一个空抽屉没有意义。

因此功能按钮在占位状态下**不显示**，与前面「四项功能禁用」的处理一致 ——
不是显示了点不动，而是根本不显示。

### 顶栏在三种状态下的构成

| 状态 | 左 | 右 |
|---|---|---|
| 占位（未打开日记） | 侧栏按钮 | **功能抽屉** · 保存状态 |
| 已打开日记 | 侧栏按钮 | 功能抽屉 · 预览切换 · 保存状态 |

两个按钮在任何状态下都同级、都显示。

**「备份设置」不再是顶栏按钮**，它已移入功能抽屉，与其余四项并列。

**不再有「返回」按钮**：编辑器就是主界面，没有上一层可退。
这是导航压平的一部分，不是遗漏。

## 六、不做

- 不改动数据层。0.2 的容器模型与迁移保持不变。
- 不引入字符串资源抽取（属多语言支持，排在前面）。
- 不改动备份、查找、导出、复制、时间五项功能的行为。
  唯一的关联是：编辑器成为主界面后，这些功能在占位状态下应当禁用，
  因为它们都需要一篇已打开的日记。

---

## 七、验收标准

- [ ] 启动后主界面是编辑器，处于占位状态
- [ ] 占位状态下编辑区不可输入，快捷输入栏不出现
- [ ] 侧栏目录是唯一的目录，主界面不再重复展示列表
- [ ] 手机上侧栏从左边划出并覆盖内容（含横屏）
- [ ] 平板上侧栏常驻并与编辑器并排
- [ ] 两种形态共用同一份侧栏内容
- [ ] 从侧栏点选日记，主界面直接切换到该篇
- [ ] 在侧栏切换日记不累积返回栈
- [ ] 占位状态下「写日记」可用，四项编辑功能入口不显示
- [ ] 占位状态下功能抽屉可打开，且其中只有「备份」一项
- [ ] 侧栏按钮与功能抽屉按钮在任何状态下都在同一顶栏、同级
- [ ] 顶栏不再有「返回」按钮
- [ ] 备份设置只能从功能抽屉进入
- [ ] 杀进程重启后，恢复上次打开的日记（若已接上该行为）

## 八、与其他工作的关系

- **多语言支持**排在前面。本次改动会新增若干界面文案，
  先抽字符串再做，比做完再抽便宜。
- **`小记`** 不受影响。它的数据模型与本改动无关。
