# 时刻日记 — Beta 0.2.1 策划案

> 版本：0.2.1 (1)
> 状态：待确认
> 上一版：0.2 (1)

---

## 一、要解决的问题

### 问题：目录出现了两次

0.2 之后，同一份内容在界面上出现了两遍：

```
主界面  = 当前日记本的日记列表     ← 一份目录
侧栏上半 = 当前日记本的日记目录     ← 同一份目录，再来一遍
```

这是 0.2 重构留下的，不是新引入的：当时把「全部日记」换成「当前本的目录」，
但主界面仍然是列表，于是侧栏与主界面展示的是同一批东西。

### 结论：主界面即编辑器

取消「列表页」这一层。主界面直接是编辑器，**默认不打开任何日记**，
显示占位状态。要写作或要继续写，从侧栏目录点击，或按「写日记」新建。

```
┌──────────────┬────────────────────────────────┐
│ 时刻日记      │  写作                          │
├──────────────┤  ──────────────────────────    │
│ 今日          │                                │
│ 昨天          │  选择一篇日记，                │
│ 10-08        │  或按右下角开始新的。           │
│  ·           │                                │
│  ·  （侧栏）  │                                │
│  ·            │                                │
├──────────────┤                                │
│ 日记本        │                                │
│  我的日记 ●   │                                │
│  2026 年      │                                │
└──────────────┴────────────────────────────────┘
```

这样侧栏是唯一的目录，不再重复。

## 二、占位状态

主界面在未打开日记时显示：

- 顶栏保留（有侧栏按钮、备份设置入口）
- 编辑区显示引导文案，**内容不可点击**：引导用户从侧栏打开，或按按钮新建
- **快捷输入栏整体不出现**（没有日记可插入时间或图片）
- 「写日记」按钮照常可用

关键约束：**不能在无日记状态下让用户输入**。否则用户敲了字却无处归属，
要么丢字，要么悄悄创建一篇空日记。因此占位状态下整块编辑区不可编辑，
引导文案本身也不是按钮 —— 它是说明，不是入口。

### 占位状态下的功能可用性

四项基本功能（复制 / 查找 / 导出 / 时间）都需要一篇已打开的日记，
因此在占位状态下**禁用**。禁用方式沿用 0.2 对新建按钮的做法：
不显示入口，而不是显示了点不动。

## 三、导航结构变更

现有两级路由将被压平。

| 现状 | 改为 |
|---|---|
| `HOME` → 列表页 | **取消**，不再有独立的列表页 |
| `EDITOR/{entryId}` → 编辑器 | 编辑器成为根，路由为 `EDITOR/{entryId?}`，id 可缺省 |
| 侧栏目录点击 → 进入 `EDITOR/{id}` | 同上，切换当前日记 |

要点：

- 编辑器成为**根目标**，`entryId` 允许缺省，缺省即占位状态。
- 从侧栏切换日记时，**不产生新的返回栈**（它是「换一篇」而不是「进一层」），
  否则用户按返回会一层层退回去，体验割裂。
- 退出编辑器不再需要「返回」按钮 —— 它已是主界面。返回键在占位状态下
  应退出应用（或回到桌面），而不是留在应用内的某个中间页。

## 四、侧栏形态（已确认）

**一律是侧栏，不是抽屉。**

这一点需要写清楚，因为它与当前实现不同：现有代码用的是
`ModalNavigationDrawer` —— Material 的**临时遮罩抽屉**，从左侧覆盖在内容之上。
侧栏则是与内容**并排、常驻**的。

| | 抽屉 | 侧栏 |
|---|---|---|
| 与内容的关系 | 覆盖在上面 | 并排 |
| 是否常驻 | 临时，用完关闭 | 常驻可见 |
| 对内容的挤压 | 不挤压（盖住） | 挤压（内容变窄） |

### 两种宽度下的表现

- **宽度足够**（平板、横屏、折叠屏展开）：侧栏常驻并排，编辑器占剩余宽度。
- **宽度不足**（手机竖屏）：侧栏**滑入并挤压编辑器**，而不是覆盖。

窄屏下挤压而非覆盖，会带来一个必须处理的问题：**编辑器在很窄的宽度下
仍要可读**。若挤压后宽度小于可读下限，则侧栏改为临时覆盖 —— 这是例外，
但要明确写出触发条件，而不是凭感觉。

两种形态共用同一份侧栏内容函数，只是容器不同。

### 已确认的其他两点

1. **侧栏下半段（日记本列表）保留。**
2. **占位文案不可点击**，只作引导。

## 五、不做

- 不改动数据层。0.2 的容器模型与迁移保持不变。
- 不引入字符串资源抽取（属多语言支持，排在前面）。
- 不改动备份、查找、导出、复制、时间五项功能的行为。
  唯一的关联是：编辑器成为主界面后，这些功能在占位状态下应当禁用，
  因为它们都需要一篇已打开的日记。

---

## 六、验收标准

- [ ] 启动后主界面是编辑器，处于占位状态
- [ ] 占位状态下编辑区不可输入，快捷输入栏不出现
- [ ] 侧栏目录是唯一的目录，主界面不再重复展示列表
- [ ] 侧栏与内容并排，不覆盖；窄屏下滑入并挤压编辑器
- [ ] 挤压后宽度不足可读下限时，退化为临时覆盖
- [ ] 从侧栏点选日记，主界面直接切换到该篇
- [ ] 在侧栏切换日记不累积返回栈
- [ ] 占位状态下「写日记」可用，四项基本功能禁用
- [ ] 杀进程重启后，恢复上次打开的日记（若已接上该行为）

---

## 七、与其他工作的关系

- **多语言支持**排在前面。本次改动会新增若干界面文案，
  先抽字符串再做，比做完再抽便宜。
- **`小记`** 不受影响。它的数据模型与本改动无关。
