# 时刻日记 — Beta 0.2 策划案

> 版本：0.2 (1)
> 状态：架构重构已交付；「基本功能」待实现
> 对照清单见 [FEATURES.md](../FEATURES.md)

## 一、0.2 的范围

0.2 分两部分。

**第一部分：修结构性缺陷**（已交付，详见 [CHANGELOG](../docs/CHANGELOG.md)）

实机试用后暴露出三个设计错位——功能都在，用起来不对：

| # | 问题 | 本质 |
|---|---|---|
| 1 | 首次启动不问备份目录，备份功能实际上从未生效过 | **有权能，无入口** |
| 2 | 主界面是扁平的全部日记列表，日记本沦为过滤器 | **信息架构错位** |
| 3 | 重启后回到「全部日记」，上次打开的日记本丢失 | **状态不持久** |

**第二部分：基本功能**（本文件第五至七节）

企划「基本功能」一节的四项，位于编辑界面右上角的抽屉中，与左上侧栏按钮同级：

| 功能 | 一句话 |
|---|---|
| `复制日记` | 复制当前日记的正文，或标题+正文+创建时间 |
| `查找` | 在**本篇 / 本日记本 / 所有日记本**中搜索关键词 |
| `导出` | 导出为 TXT，或导出为一张长图 / 切分的几张短图 |
| `时间` | 修改这篇日记的创建时间 |

**推迟到后续版本**：`小记`、`时间轴 / 日历预览`、`心情与天气`。
这三项属于特色功能，其中小记需要新的数据模型（当天草稿 → 日终合并），
不在本版范围内。

## 二、信息架构重构（问题 2 与 3）

### 2.1 现状与目标

**现状**

```
主界面  = 全部日记（按时间倒序的扁平列表）
侧栏上半 = 「全部日记」   ← 一个筛选入口
侧栏下半 = 日记本列表
新建日记 = 有条件（选中某本时归入该本，否则 bookId = null）
```

**目标**

```
主界面  = 当前打开的日记本中的日记
侧栏上半 = 当前日记本的日记目录（可跳转到指定日记）
侧栏下半 = 日记本列表（新建 / 切换 / 删除）
新建日记 = 无日记本时禁止
```

核心转变：**日记本从「分类标签」升格为「容器」**。
一篇日记必然属于且仅属于一个日记本，不再是可选的归属关系。

### 2.2 数据模型变更：分两步走

`Entry.bookId` 最终要由 `Long?` 改为 `Long`（非空），但**不在 0.2 完成**。

**为什么拆开**

一次做完「非空约束 + 外键改 CASCADE」是破坏性操作，而它依赖两个尚未验证的前提：
`.mjb` 恢复流程从未在真实数据上跑过一轮，用户的历史数据也没有样本。
一旦迁移出问题，既没有退路也没有回滚依据。拆成两步后，第一步非破坏且可重跑，
先在实际使用中验证，再上约束。

| 版本 | 迁移 | 内容 | 破坏性 |
|---|---|---|:--:|
| **0.2** | 1 → 2 | 确保存在默认日记本；回填 `book_id` 为空的记录 | 否，可重跑 |
| **0.3** | 2 → 3 | `book_id` 加非空约束；外键由 `SET NULL` 改为 `CASCADE` | 是 |

**0.2 的迁移（非破坏）**

```
1. 不存在任何日记本时，以「我的日记」为名创建一个
2. UPDATE entries SET book_id = <默认本 id> WHERE book_id IS NULL
```

要点：

- 全程在事务内，失败整体回滚，不留半完成状态。
- 可重复执行——第二次运行因无空值记录而成为空操作。
- **外键保持 `SET NULL`**。因此 0.2 期间删除日记本，其日记仍退回「未分类」
  且 `book_id` 重新变为空。这是过渡期的已知不一致：主界面不再有「全部日记」
  入口，这些日记会没有归属。**对策**：0.2 的删除日记本操作，在删除前先把
  该本内的日记迁移到默认本，而不是让它们失去归属。

> 代码层面，`Entry.bookId` 在 0.2 仍保持 `Long?`。类型如实反映数据库约束，
> 不用非空类型粉饰一个仍可为空的列。到 0.3 加约束时一并收紧。

**0.3 的迁移（破坏性，届时详述）**

届时具备两个前提才执行：`.mjb` 恢复流程已端到端验证通过，且 0.2 的过渡迁移
已在真实数据上运行一段时间。迁移前强制做一次备份，确认文案写明将删除的条数。

### 2.3 当前日记本的持久化

上次打开的日记本记入偏好存储，冷启动后自动恢复，恢复逻辑：

```
读偏好 → 该 id 的日记本仍存在？ → 打开它
                              ↓ 否（已被删除）
                        回退到最近创建的日记本
                              ↓ 一个日记本都没有（不该发生，但必须处理）
                        进入引导态，提示创建
```

### 2.4 空态与禁用逻辑

| 状态 | 主界面 | 新建按钮 | 侧栏 |
|---|---|---|---|
| 有日记本、本内无日记 | 「还没有日记」+ 引导 | 可用 | 上半段为空 |
| 无日记本（仅理论可能） | 「先创建一个日记本」 | **禁用** | 下半段为引导 |

用户明确要求：**未打开日记本时不能新建日记**。因此该约束落到 UI 层：
无当前日记本时，新建按钮置灰并附文字说明，而不是点击后无声失败。

## 三、存储位置与初次启动（问题 1）

### 3.1 现状

`MjbBackupManager.backup()` 逻辑完整，恢复逻辑完整，但：

- `BackupScheduler.setBackupTreeUri` **没有任何调用者**
- 权限从未申请，`isConfigured()` 恒为 false
- 因此三个触发点（冷启动 / 退后台 / WorkManager）全部空转

**即备份在 0.1 中从未真正执行过一次。**

### 3.2 首次启动引导

启动时检测备份是否已配置，未配置则弹出引导页（非可跳过的一次性弹窗）：

```
你的日记存放在哪里？

时刻日记需要你指定一个文件夹，用来存放备份。
备份是 ZIP 归档，包含全部日记与图片，随时可以导入回来。

        [ 选择文件夹 ]        [ 稍后再说 ]
```

选择后即刻执行一次备份，让用户确认「它真的写进去了」，而不是等下次冷启动。

**「稍后再说」的后果必须明说**：顶部常驻一条提示条
「备份未配置，日记仅存于本机」。不静默失败，也不反复弹窗骚扰。

### 3.3 目录失效的处理

用户可能删除文件夹、卸载 SD 卡、撤销授权。检测与处理：

| 情形 | 处理 |
|---|---|
| 冷启动时目录不可访问 | 提示条转为警示，引导重新选择 |
| 备份时写入失败 | 记录失败原因，提示条显示「上次备份失败：<原因>」 |
| 用户更换目录 | 询问是否将旧目录的归档迁移过去；不迁移也可用，只是归档分散 |

### 3.4 备份界面

0.1 有逻辑无界面，0.2 补齐一个设置页：

- 当前备份位置（含「更换」）
- 上次成功备份时间 / 上次失败原因
- 「立即备份」按钮，执行中显示进度，完成显示归档名与体积
- 「从归档恢复」，选定 `.mjb` 后先展示其中的 manifest 内容
  （时间、条目数、图片数）**再**要求确认，确认文案写明当前数据将被覆盖

## 四、基本功能设计

四项入口统一放在编辑界面右上角的抽屉里，与左上侧栏按钮同级。

### 4.1 复制日记

两种粒度，让用户选：

- **仅正文**
- **标题 + 正文 + 创建时间**

复制结果为**纯文本**还是**Markdown 源文本**？这里选 Markdown 源文本：

理由是本应用的正文本身就是 Markdown，`![time]` / `![img]` 等嵌入都是文本形式。
复制成纯文本会丢掉全部样式与嵌入，复制到别处就失去了原貌；
而 Markdown 源文本粘回本应用任意一篇日记都能还原。若用户要纯文本，
在粘贴目标处自行处理即可；反过来则无法还原。

这意味着复制走系统剪贴板，且**不做任何渲染**。

### 4.2 查找

范围三档，与企划一致：

| 范围 | 查询 |
|---|---|
| 本篇日记 | 当前编辑的正文与标题 |
| 本日记本 | 当前日记本内的全部日记 |
| 所有日记本 | 跨全部日记本 |

**「所有日记本」不恢复全局视图。** 这一点需要说明：0.2 取消了「全部日记」入口，
把日记本确立为容器。跨本查找并不与它冲突 —— 查找是**临时的、以查询为驱动的**
视图，结果是一次搜索结果列表，而非一个可以常驻浏览的「所有日记」入口。
查完关闭即结束，不改变当前打开的日记本。

实现用 SQL `LIKE` 而非全文检索（FTS）。理由：日记规模是千条量级，
`LIKE '%关键词%'` 在这个量级下毫秒级返回，而 FTS 需要额外的虚拟表、
分词配置与迁移负担。若将来条目数增长到影响体验，再引入 FTS 不迟。

结果列表展示：日记标题 + 命中片段（关键词前后各若干字）+ 所属日记本 + 时间。
点击跳转到该日记。

### 4.3 导出

三种目标，前两种难度差异很大：

**TXT — 简单。** 直接输出 Markdown 源文本。同时导出一个 `.md` 更实用，
所以实际提供两个选项：`.txt`（纯文本，嵌入标记会被剥离或原文保留）与 `.md`。

**一张长图 — 中等，是本项的主要工作量。**

做法：用 Compose 的绘制能力把整篇日记渲染到一个超高画布上，再导出为 PNG。
要点：

- **不能复用屏幕上的 Composable**，那样受屏幕尺寸约束。需要一条独立的、
  以宽度为固定值（如 1080px）、高度自适应的渲染路径。
- 高度需要**先测量后绘制**：Compose 无法一次性给出未知内容的最终高度，
  需先用 `SubcomposeLayout` 或测量文本生成一遍以确定总高。
- 图片嵌入要参与排版，因此图片必须先解码并按其宽高比计算占位高度。
- 超长日记会产生极高的位图（10 万像素量级），**有 OOM 风险**。
  需要设置高度上限，超过即自动转为「切分多张」模式。

**切分短图 — 在长图的基础上按固定高度切片。** 因此长图做完，切图是顺带的。

导出走 SAF（`CreateDocument`），让用户选保存位置，与备份目录同一套权限模型。

### 4.4 时间

修改当前日记的创建时间。

- 界面给一个日期时间选择器，默认值为当前创建时间。
- 保存后 `createdAt` 被改写，`updatedAt` 随之更新。
- **列表排序依赖 `createdAt`**，因此修改后日记会跳到列表相应位置，这是预期行为，
  不是 bug。界面上应提示这一点，避免用户以为日记丢了。

风险：把创建时间改到未来，会让日记排到列表最前。不禁止，但选择器限制在
合理范围内（不早于 1970，不晚于当前时间 + 1 天）。

## 五、0.2 不做的事

| 项 | 理由 |
|---|---|
| `小记` | 需要新数据模型（当天草稿 → 日终合并），且合并涉及不可逆删除。在备份恢复流程验证通过之前，不做不可逆操作 |
| `时间轴 / 日历预览` | 依赖小记的时间粒度语义，先定数据模型再谈视图 |
| `心情与天气` | 作为 MD 扩展语法新增两个标签，改动面小，但排在基本功能之后 |
| 云备份（WebDAV / FTP / SMB） | `.mjb` 格式尚未经过一轮完整恢复验证，先验证再扩散 |
| 地点插入 | 独立性强，不阻塞本版；若有余量再纳入 |
| 编辑器背景 / 全局字体 / 光标选项 | 装饰性 |
| MD3 Expressive | 上游仍在变动 |
| 5 分钟精确定时备份 | Doze 会压制周期任务，承诺做不到的周期比不承诺更糟 |

## 六、验收标准

**存储**

- [ ] 全新安装启动后，被要求指定备份目录
- [ ] 选定目录后立即产出一个 `.mjb`，`%i/MomentJournal/Backups` 下可见
- [ ] 点「稍后再说」后，主界面有常驻提示，且不重复弹窗
- [ ] 撤销文件夹授权后，下次启动提示条转为警示
- [ ] 「立即备份」可手动触发并显示结果；失败时能看到原因
- [ ] 恢复流程在覆盖数据**之前**展示归档内容并要求确认

**信息架构**

- [ ] 主界面只显示当前日记本的日记
- [ ] 侧栏上半段是该本的日记目录，点击可跳转
- [ ] 侧栏下半段管理日记本，切换后主界面立即跟随
- [ ] 无日记本时新建按钮禁用，且有文字说明原因
- [ ] 杀进程重启后自动回到上次打开的日记本
- [ ] 删除日记本时确认框写明将删除多少篇日记

**基本功能**

- [ ] 编辑界面右上角抽屉中可进入四项功能
- [ ] 复制：两种粒度均可用，粘贴后嵌入标记与样式完整保留
- [ ] 查找：三档范围各自返回正确结果，跨本查找后可关闭且不改变当前日记本
- [ ] 导出 TXT 与 .md 均可保存到用户选定位置
- [ ] 导出长图在超长日记下不 OOM，超限时自动转为切分模式
- [ ] 导出切图可指定张数或按固定高度切分
- [ ] 修改创建时间后列表位置随之改变，且有提示说明

**数据**

- [ ] 0.1 产生的数据可无损迁移到 0.2（含 `bookId` 为 null 的日记）
- [ ] 迁移后不存在 `book_id` 为空的记录
- [ ] 首次启动必然存在至少一个日记本
- [ ] 迁移可重复执行，第二次运行不产生任何变化
- [ ] 删除日记本时，其中的日记先迁入默认本，不出现无归属的日记
      （注：非空约束与级联删除属 0.3，本版不验收）

## 七、实现顺序

依赖关系决定顺序，与重要性无关：

1. **偏好存储层** —— 当前日记本与备份位置都要用，先有它。
2. **迁移 1 → 2（非破坏）** —— 建默认本、回填空值。影响面最大，必须早做，
   否则后续都在旧模型上写。
3. **备份授权引导 + 备份设置页** —— 独立于架构重构，可并行。
4. **侧栏上半段改为当前日记本的目录；主界面改为该本的日记** —— 依赖 1 与 2。
5. **空态与禁用逻辑**。
6. **恢复流程的界面与确认**。
7. **基本功能抽屉** —— 四项共用同一个入口。
8. **复制与时间** —— 最简单，先易后难，用来验证抽屉与交互是否顺手。
9. **查找** —— DAO 查询 + 结果页。
10. **导出** —— 本版最重的一项，长图渲染需先做布局测量那一层。

## 八、风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 迁移破坏用户数据 | 0.2 的迁移本身非破坏，但会改写 `book_id` | 事务内完成，失败回滚；可重复执行；破坏性的非空约束推迟到 0.3 |
| 过渡期外键语义不一致 | 0.2 仍为 `SET NULL`，删本会产生无归属日记 | 删除日记本时先把其中日记迁入默认本 |
| 删除日记本连带删日记 | 语义变化，用户可能按 0.1 的习惯操作而误删 | 确认框写明条数；备份到位后才允许删除 |
| SAF 目录授权不稳定 | 部分设备上 `DocumentFile` 行为不一致 | 每次使用前重新校验可写性，不缓存「可用」的判断 |
| 主界面改动较大 | 一次改到列表、侧栏、导航三处 | 先落数据层与偏好层，UI 分两次改 |
| 导出的长图可能 OOM | 超长日记需要极高的位图 | 设高度上限，超限即自动转为切分模式 |
| 修改创建时间引起排序跳动 | 用户可能误以为日记丢失 | 列表位置变化符合预期，但需在界面提示 |
| 跨本查找被误解为恢复全局视图 | 与刚确立的容器模型概念上易混 | 查找结果是一次性列表，不常驻、不改变当前日记本 |
